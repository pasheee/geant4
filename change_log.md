# Журнал изменений проекта (Change Log)

Этот файл содержит подробное описание всех изменений, вносимых в программный код (C++ часть на базе Geant4 и Python-скрипты для анализа). Цель данного журнала — фиксация технических деталей, физических обоснований и логики изменений для последующего использования при написании научной статьи (LaTeX).

## Формат записей
Каждое существенное изменение будет фиксироваться по следующему шаблону:
* **Дата / Задача:** Краткое описание решаемой задачи.
* **Что изменено:** Конкретные файлы и функции, подвергшиеся модификации.
* **Физический/технический смысл:** Зачем это было сделано и как это влияет на результаты симуляции или анализа.

* **Дата / Задача:** 15.04.2026 / Изменение схемы расстановки ФЭУ с кольцевой на концентрическую.
* **Что изменено:** 
  - `sim/source/construction.cc`: Изменён алгоритм расстановки ФЭУ. Теперь на верхней и нижней крышках располагаются по 19 ФЭУ в виде концентрических колец: 1 в центре ($r = 0$), 6 в среднем кольце ($r = 250$ мм) и 12 во внешнем кольце ($r = 500$ мм). Установлены новые идентификаторы (copy number): верхняя крышка 0–18, нижняя крышка 19–37.
  - `sim/source/pmtSD.cc`: В методе `PMTSD::ProcessHits` обновлено условие идентификации верхних и нижних ФЭУ с `copyNumber < 12` на `copyNumber < 19`.
* **Физический/технический смысл:** Равномерное заполнение торцов детектора фотоэлектронными умножителями (паттерн гексагональной упаковки) позволяет существенно увеличить телесный угол сбора света, а также делает регистрацию черенковских фотонов более однородной по площади крышек, снижая краевые эффекты.

* **Дата / Задача:** 19.04.2026 / Настройка визуализации детектора в Geant4 (исправление непрозрачного серого куба).
* **Что изменено:**
  - `sim/source/construction.cc`:
    - Добавлен метод `logicWorld->SetVisAttributes(G4VisAttributes::GetInvisible());` для логического объёма мира, чтобы он не закрывал собой внутренние части детектора.
    - Исправлены цвета `G4Color` в `G4VisAttributes`. Ранее значения задавались в диапазоне 0-255 (например, `G4Color(255, 0, 0, 1)`), что приводило к некорректной заливке, поскольку конструктор ожидает значения от 0.0 до 1.0. Заменены на диапазоны 0.0-1.0 с корректными значениями прозрачности (alpha).
    - Для стального бака (`logicSteelTank`) принудительно установлен режим wireframe (`SetForceWireframe(true)`), чтобы он не скрывал геометрию детектора.
  - `sim/vis.mac`: 
    - Раскомментирована строка `/vis/geometry/set/visibility logicWorld false` для дополнительной гарантии невидимости куба воздуха.
    - Изменена прозрачность `logicSteelTank` с `1.0` (непрозрачный) на `0.2` (полупрозрачный).
* **Физический/технический смысл:** Исправление параметров OpenGL-рендера позволяет в графическом интерфейсе Geant4 (UI) наглядно видеть внутреннюю структуру детектора (воду, колбу, расположение всех ФЭУ), что критично для валидации правильности построения геометрии без необходимости "заглядывать" внутрь через код.

* **Дата / Задача:** 19.04.2026 / Анализ захвата тепловых нейтронов (сравнение Cd и Gd).
* **Что изменено:**
  - `sim/source/physics.cc`: В `PhysicsList` добавлены адронные конструкторы `G4HadronPhysicsFTFP_BERT_HP`, `G4HadronElasticPhysicsHP`, `G4IonPhysics` и `G4DecayPhysics`. Это позволяет корректно моделировать процессы упругого рассеяния, замедления (термализации) и радиационного захвата нейтронов (Neutron Capture) с использованием высокоточных баз данных (High Precision - HP).
  - `sim/source/construction.cc`: Добавлена возможность переключения допанта через новую UI команду `/det/dopant`. Теперь можно выбрать `Cd` (кадмий), `Gd` (гадолиний) или `None` (чистая вода). Смеси создаются на основе добавления 0.1% массовой доли нужного элемента.
  - `sim/source/generator.cc`: Логика равномерного разыгрывания начальной позиции (внутри PMMA колбы) теперь отвязана от режима `ibd` и управляется флагом `/gen/randomizePos true`. Это позволяет запускать `mono` нейтроны изотропно по всему объёму детектора.
  - `sim/source/action.cc`: Реализован `SteppingAction`, который отслеживает первичные нейтроны (`ParentID == 0`). В момент их гибели (статус `fStopAndKill` от захвата) записывается их полное время жизни (global time) в файл. Имя файла настраивается макросом `/analysis/neutronLifetimeFile`.
  - `NIRS/make_plots_data.py`: Добавлено чтение файлов `neutron_lifetime_Cd.txt` и `neutron_lifetime_Gd.txt`, перевод времени из нс в мкс и построение гистограмм времени жизни (файлы `lifetime_hist_Cd.dat` и `lifetime_hist_Gd.dat`). Добавлена логика парсинга файлов сбора фотоэлектронов (`pe_cd.txt` и `pe_gd.txt`) для генерации гистограмм Npe при захвате нейтрона (файлы `npe_hist_Cd.dat` и `npe_hist_Gd.dat`).
* **Физический/технический смысл:** Нейтроны, рождающиеся при IBD, перед захватом должны термализоваться (замедлиться до энергий порядка долей эВ), что занимает время порядка десятков микросекунд. Сравнение допантов Cd и Gd позволяет определить, какой из них обеспечивает меньшее среднее время жизни нейтрона, что напрямую влияет на ширину временного окна совпадений (coincidence window) при выделении сигнала IBD от фона. Кроме того, гамма-каскад при захвате (около 8 МэВ для Gd и 9 МэВ для Cd) генерирует комптоновские электроны, производящие черенковское излучение. Сравнение распределений Npe (количества фотоэлектронов) необходимо для определения порога регистрации и сравнения энергетического отклика детектора при использовании разных допантов.

* **Дата / Задача:** 19.04.2026 / Равномерный сэмплинг позитронов и сбор расширенной статистики (для графиков).
* **Что изменено:**
  - `sim/source/generator.cc`: Для режима `ibd` добавлена генерация начальной позиции позитрона, равномерно распределённой по объёму центральной колбы (PMMA vessel). Координаты $r$, $\phi$, $z$ разыгрываются случайным образом в пределах $R \in [0, 589]$ мм и $Z \in [-349, 349]$ мм.
  - `sim/macros/batch_nirs.mac`: Изменён флаг `/gen/isotropic` на `true`, чтобы позитроны разлетались во все стороны. Число событий увеличено до 10000 для набора лучшей статистики.
  - `sim/source/pmtSD.cc`: Добавлен подсчёт количества сработавших ФЭУ (размер словаря `fPhotoElectronsPerPMT`) в событии. Это значение записывается 6-й колонкой в файл `pe_asymmetry.txt`.
  - `NIRS/make_plots_data.py`: Скрипт дополнен парсингом новой колонки `N_fired_PMTs`. На её основе строится график профиля (mean) сработавших ФЭУ от энергии позитрона $T_e$. Также добавлено построение 1D-гистограмм собранных фотоэлектронов ($N_{pe}$) для срезов по энергиям позитрона: 2-3 МэВ, 5-6 МэВ и 8-9 МэВ.
* **Физический/технический смысл:** Равновероятное разыгрывание позитронов по объёму и углу имитирует реальное пространственное распределение взаимодействий IBD в детекторе (реакторное антинейтрино может провзаимодействовать с протоном в любой точке мишени). Сбор статистики по числу сработавших ФЭУ (multiplicity) и гистограммам фотоэлектронов позволяет оценить энергетическое разрешение детектора и порог триггера.

* **Дата / Задача:** 19.04.2026 / Сбор статистики по генерации черенковских фотонов для разных энергий позитронов.
* **Что изменено:**

В конце каждого события количество рожденных фотонов записывается в файл (по умолчанию `photons_per_event.txt`). Команда конфигурации вывода: `/analysis/photonsPerEventFile`.

  - `sim/macros/pos_p10.mac`, `pos_p50.mac`, `pos_p90.mac`: Созданы и выполнены макросы для запуска симуляции моноэнергетичных позитронов с соответствующими энергиями для генерации файлов `photons_p10.txt`, `photons_p50.txt`, `photons_p90.txt`.
  - `NIRS/make_plots_data.py`: Добавлено чтение файлов с фотонами для построения гистограмм распределения количества сгенерированных оптических фотонов для каждой из энергий. Создаются файлы `photons_hist_p10.dat`, `photons_hist_p50.dat` и `photons_hist_p90.dat`.
* **Физический/технический смысл:** Черенковское излучение имеет пороговый характер и выход фотонов зависит от кинетической энергии частицы и пройденного пути до остановки. Распределение числа сгенерированных фотонов (а не только собранных ФЭУ фотоэлектронов) позволяет оценить фундаментальный лимит энергетического разрешения детектора, обусловленный флуктуациями числа фотонов, без учета квантовой эффективности ФЭУ и оптических потерь в среде.

* **Физический/технический смысл:** Прежний график со сплошной заливкой создавал визуальный артефакт: у Cd около $76\%$ событий имеют $N_{pe}\le 8$ (медиана $=8$), что формирует огромный левый пик ($36\,903$ событий в первом бине), визуально «перевешивающий» Gd, хотя физически для триггерного отбора delayed-сигнала важен правый хвост (события с большим числом фотоэлектронов). После переработки: (а) логарифмическая ось $Y$ в гистограмме делает видимыми хвосты до $N^{tot}_{pe}\sim 250$ и показывает, что красная кривая Gd лежит выше синей Cd на всём «информативном» участке; (б) кривая выживания напрямую отвечает на вопрос «какая доля событий захвата даёт сигнал не ниже порога $N^{tot}_{pe,thr}$» --- кривая Gd монотонно выше Cd, что соответствует физическому ожиданию «выше = лучше». Тем самым график теперь корректно отражает преимущество Gd как допанта.
